# ИИ-краулер для аудита сайтов школ и детских садов (Госвеб, Магаданская область)

Краулер автоматически обходит официальные сайты 40 школ и 40 детских садов на платформе «Госвеб»,
проверяет актуальность и полноту контента, определяет **эталонный сайт** для каждого типа учреждений,
сравнивает с ним остальные сайты и формирует понятный отчёт: где проблема, насколько она критична
и что исправить в первую очередь.

Решение подготовлено ИИ-агентом (ветка `AI-only-solution`).

## Отчёт о проверке моделей

7 ноября 2026 года четыре модели проверили на одной выборке из 24 новостей школ и детсадов и 6 искусственных примеров. Задача — определить дату события или вернуть `null`, если текст не позволяет установить один день. Разметку подготовил Codex. Независимой проверки человеком пока не было.

| Модель | Верно из 30 | Верно на реальных новостях из 24 | Ошибочно выдана дата | Медиана ответа |
| --- | ---: | ---: | ---: | ---: |
| Gemini 2.5 Flash | 29 | 23 | 1 | 4,03 с |
| Qwen3.5 9B, локально | 25 | 20 | 1 | 3,51 с |
| Gemini 2.5 Flash-Lite | 25 | 19 | 5 | 1,72 с |
| Qwen3 14B, локально | 21 | 15 | 9 | 5,19 с |

Для показа извлечения дат выбран **Gemini 2.5 Flash** с уточнённой инструкцией и выключенным поиском. По расходу на реальных новостях девять запросов обойдутся примерно в **$0,018**. Тарифная стоимость токенов во всех 62 успешных платных запросах составила **$0,06756**. Отдельное списание за поиск шлюз не сообщил.

Штатный фактчекинг с веб-поиском проверили отдельно. Например, Gemini присвоила статус «подтверждено» участию магаданской гимназии в «Атомном диктанте», хотя сослалась на мероприятия в Калуге и Омске. Перед показом такого вывода нужно сверить учреждение в источнике. [Полный отчёт с примерами, стоимостью и ответами моделей](benchmarks/paid-comparison.md) · [Локальные прогоны на RTX 4080](benchmarks/README.md) · [Готовый HTML-отчёт по сайтам](reports/latest/index.html)

## Быстрый старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m audit run                       # все 80 сайтов -> reports/latest/index.html
.venv/bin/python -m audit run --only sh-ola,ds5     # выборочно (подстроки доменов)
.venv/bin/python -m audit run --kind kindergarten   # только детские сады
.venv/bin/python -m audit run --llm                 # + факт-чекинг новостей ИИ-агентом (см. ниже)
```

Настройки ИИ — в файле `.env` (см. `.env.example`) или флагами; подробно — раздел [«Настройка ИИ»](#настройка-ии).
Проверить подключение одной командой: `.venv/bin/python -m audit llm-test`.

## Что проверяется

| Раздел | Школы | Детские сады | Проверка |
|---|:-:|:-:|---|
| Новости | ✓ | ✓ | интервал между публикациями ≤ 14 дней (за год, летние каникулы отмечаются мягче); давность последней новости; публикация ≤ 24 ч после события (дата события из текста: «23 октября», «21–25 сентября», «вчера»); **факт-чекинг** |
| Мероприятия | ✓ | (если есть) | наличие на текущий и следующий квартал; прошедшие мероприятия сверяются с новостями (новость в течение 2 недель) |
| Документы / Сведения об ОО | ✓ | ✓ | полный перечень документов со всех подразделов; 20 обязательных категорий (Приказ Рособрнадзора № 1493); актуальность отчёта о самообследовании; пустые подразделы; **сравнение с эталоном и другими сайтами** |
| Педагогический состав / Наш коллектив | ✓ | ✓ | фото (включая выявление силуэтов-заглушек шаблона), уровень образования, контакты (для детсадов) — по карточкам каждого сотрудника |
| О школе, Структура и органы управления | ✓ | | история учреждения, заполненность, фото руководителей, пустые страницы органов управления |
| Контакты / главная страница | ✓ | ✓ | телефон, e-mail, адрес, режим работы, часы приёма; для детсадов — контакты и режим работы на главной |
| Расписание | ✓ | | факт заполнения (модуль шаблона, файлы, картинки), актуальный учебный год |
| Реализуемые образовательные программы | ✓ | ✓ | наименования, форма, срок, язык, численность, тексты программ |
| Педагогам и сотрудникам | ✓ | ✓ | заполненность подразделов |
| Весь сайт | ✓ | ✓ | демо-контент шаблона из памятки «Типичные ошибки»: «Укажите ФИО», «Заголовок мероприятия №1», «Опишите…», «Примерно от … до … символов», «Задача 1», «статус», «Сайт в стадии разработки»; баннер ПОС |

### Факт-чекинг новостей
1. **Офлайн (бесплатно, всегда):** даты государственных праздников и памятных дат (32-ФЗ, указы Президента РФ,
   День Магаданской области), «N-летия» исторических событий и персоналий, соответствие дня недели дате,
   событие «в прошедшем времени» с датой позже публикации, сверка с разделом «Мероприятия».
2. **ИИ-агент (опция `--llm`, см. «Настройка ИИ»):** модель с веб-поиском (Gemini + Google Search через
   OpenAI-совместимый шлюз или Claude + web search; локальные модели — без поиска) определяет дату события и проверяет до 4 фактов новости по открытым источникам
   (официальные сайты, СМИ), возвращает JSON: подтверждено / расхождение / не подтверждено + источник.
   «Подтверждено» без найденных источников не засчитывается.

### Эталонный сайт и сравнение
Эталон — сайт с наибольшим баллом среди учреждений своего типа. Для остальных сайтов отмечаются
документы, которые есть у эталона **и** у большинства учреждений, а также разделы эталона, которых нет на сайте.
Картинки сотрудников сравниваются между сайтами по перцептивному хэшу: одинаковое изображение на нескольких
сайтах (или у нескольких сотрудников) — это заглушка шаблона.

### Критичность и балл
`Критично` (сайт недоступен, нет новостей > 45 дней, нет устава/лицензии, нет раздела педсостава) ·
`Высокая` (нарушение норм, видимые гражданам заглушки) · `Средняя` · `Низкая` (рекомендации).
Балл = 100·e^(−штраф/80), штраф 15/8/3/1, не более 25 на раздел. Шкала: ≥85 «Хорошо», ≥65 «Удовлетворительно»,
≥40 «Требует внимания», иначе «Критично».

## Настройка ИИ

ИИ используется только в режиме `--llm` (факт-чекинг новостей и уточнение даты события). Без него краулер
работает полностью и бесплатно на офлайн-проверках. Поддерживаются два типа бэкенда:

* **`openai`** — любой сервер с OpenAI-совместимым API `/v1/chat/completions`: облачные шлюзы
  (OpenRouter, LiteLLM, vLLM, корпоративный прокси) **и локальные модели** (Ollama, LM Studio, llama.cpp server, vLLM);
* **`anthropic`** — Anthropic API (Claude с серверным веб-поиском).

### Параметры

Задаются переменными окружения или в файле `.env` в корне проекта (читается автоматически, в git не попадает;
шаблон — `.env.example`). Флаги командной строки имеют приоритет над `.env`.

| Переменная | Флаг CLI | По умолчанию | Что регулирует |
|---|---|---|---|
| `AUDIT_LLM_PROVIDER` | `--llm-provider` | `auto` | `openai` / `anthropic`. `auto`: если задан `AUDIT_LLM_BASE_URL` — `openai`, иначе `anthropic` |
| `AUDIT_LLM_BASE_URL` | `--llm-base-url` | — | адрес OpenAI-совместимого сервера **до** `/chat/completions`, например `https://openrouter.ai/api/v1`, `http://localhost:11434/v1` |
| `AUDIT_LLM_API_KEY` | — (только env/.env) | — | ключ, отправляется как `Authorization: Bearer …`. Для локальных серверов не нужен — оставьте пустым |
| `AUDIT_LLM_MODEL` | `--llm-model` | `gemini-2.5-flash` (openai) / `claude-opus-5-5` (anthropic) | идентификатор модели так, как его понимает сервер (`/v1/models`) |
| `AUDIT_LLM_WEB_SEARCH` | `--llm-web-search` | `auto` | `google` — передать инструмент `googleSearch` (Gemini за прокси Vertex/LiteLLM); `off` — без веб-поиска; `auto` — `google` для моделей с «gemini» в названии, иначе `off` |
| `AUDIT_LLM_JSON_MODE` | — | `json_object` | как просить JSON: `json_object`, `json_schema` (строгая схема — vLLM, LM Studio, OpenAI) или `off`. Если сервер режим не поддерживает (HTTP 400/422), краулер сам повторит запрос без него |
| `AUDIT_LLM_TIMEOUT` | — | `120` | таймаут запроса, секунд (для локальных моделей на CPU ставьте 300–600) |
| `AUDIT_LLM_MAX_TOKENS` | — | `4000` | лимит длины ответа |
| `ANTHROPIC_API_KEY` | — | — | ключ для `anthropic` (или профиль `ant auth login`) |
| `AUDIT_CACHE_DIR` | `--cache-dir`* | `.cache` | кэш страниц и ответов ИИ (`.cache/llm/`) — повторный прогон не тратит токены |

\* `--cache-dir` задаёт кэш страниц; кэш ответов ИИ берётся из `AUDIT_CACHE_DIR`.

Сколько новостей на сайт отправлять в ИИ — флаг `--llm-news` (по умолчанию 3).

### Примеры

```bash
# Облачный OpenAI-совместимый шлюз с Gemini + Google Search
AUDIT_LLM_BASE_URL=https://<шлюз>/v1  AUDIT_LLM_API_KEY=<ключ>  AUDIT_LLM_MODEL=gemini-2.5-flash

# OpenRouter / любой OpenAI-совместимый провайдер без встроенного поиска
AUDIT_LLM_BASE_URL=https://openrouter.ai/api/v1  AUDIT_LLM_API_KEY=<ключ>  AUDIT_LLM_MODEL=qwen/qwen3-235b-a22b

# Локально: Ollama (ollama serve; ollama pull qwen2.5:14b)
AUDIT_LLM_BASE_URL=http://localhost:11434/v1  AUDIT_LLM_MODEL=qwen2.5:14b  AUDIT_LLM_TIMEOUT=600

# Локально: LM Studio (вкладка Developer → Start server)
AUDIT_LLM_BASE_URL=http://localhost:1234/v1  AUDIT_LLM_MODEL=<id модели из LM Studio>  AUDIT_LLM_JSON_MODE=json_schema

# Локально: vLLM / llama.cpp server
AUDIT_LLM_BASE_URL=http://localhost:8000/v1  AUDIT_LLM_MODEL=<имя модели>

# Anthropic API
AUDIT_LLM_PROVIDER=anthropic  ANTHROPIC_API_KEY=<ключ>
```

Разовый запуск без правки `.env`:

```bash
.venv/bin/python -m audit run --llm --llm-base-url http://localhost:11434/v1 --llm-model qwen2.5:14b
```

Проверка настроек (один тестовый запрос с новостью, в которой заведомо неверная дата Дня отца):

```bash
.venv/bin/python -m audit llm-test
.venv/bin/python -m audit llm-test --llm-base-url http://localhost:11434/v1 --llm-model qwen2.5:14b
```

### Как учитывается веб-поиск

* **С веб-поиском** (`google` или Claude) статусы «подтверждено» / «расхождение» засчитываются, только если
  в ответе есть ссылки на найденные источники — они показываются в отчёте.
* **Без веб-поиска** (большинство локальных и OpenAI-совместимых моделей) модель всё равно определяет дату
  события, но её вердикты по фактам помечаются как «не подтверждено (мнение модели: …)» и **не влияют на оценку**:
  модель без поиска может ошибаться. Пример из проверки: `gemini-2.5-flash-lite` без поиска уверенно назвала
  неверную дату Дня отца. Офлайн-проверки (памятные даты, юбилеи, дни недели) работают при любом бэкенде.
* Если у модели нет поиска, а проверка по источникам нужна, используйте модель с поиском (Gemini за прокси
  с `AUDIT_LLM_WEB_SEARCH=google`) или `anthropic`.

### Рекомендуемые модели

Задача ИИ здесь узкая: прочитать русскоязычную новость, вернуть корректный JSON и проверить факты
по открытым источникам. Поэтому важнее всего три свойства: **веб-поиск**, **стабильный JSON** и **хороший русский**.
Без веб-поиска модель полезна только для определения даты события — проверка фактов не засчитывается.

**Проверено в этой работе (полный прогон 80 сайтов, 07.11.2026):**

| Модель | Режим | Результат |
|---|---|---|
| `gemini-2.5-flash` + Google Search (через OpenAI-совместимый шлюз) | **рекомендуется по умолчанию** | 120 запросов без сбоев, все ответы — валидный JSON, источники в каждом ответе с вердиктом; нашла реальные ошибки (дата Дня отца, программа инженерного класса). ≈ $0.005 за новость |
| `gemini-2.5-flash-lite` без поиска | не рекомендуется для факт-чекинга | дёшево и быстро, дату события определяет, но уверенно ошиблась в дате Дня отца — подходит только для дат |

**Рекомендации по выбору (не проверялись в этой работе — проверьте `audit llm-test` перед использованием):**

| Сценарий | Модель | Почему |
|---|---|---|
| Максимальная точность, облако | `gemini-2.5-pro` / `gemini-3.1-pro-preview` + `AUDIT_LLM_WEB_SEARCH=google` | та же связка с Google Search, сильнее рассуждения; дороже flash в 4–5 раз |
| Anthropic API | `claude-opus-5-5` (`AUDIT_LLM_PROVIDER=anthropic`) | встроенный веб-поиск, строгий JSON по схеме; дороже Gemini Flash |
| Локально, сервер с GPU 24 ГБ+ | Qwen3 (≥ 30B, instruct) или Qwen2.5-32B-Instruct | лучший русский и JSON среди открытых моделей этого размера |
| Локально, GPU 12–16 ГБ | Qwen2.5-14B-Instruct, Gemma 3 12B | приемлемо для даты события; факты — только как «мнение модели» |
| Локально, российские модели | T-pro / T-lite (T-Технологии), YandexGPT-5-Lite-Instruct | дообучены на русском; уточните актуальную версию и лицензию |

Практические советы:
* для локальных моделей ставьте `AUDIT_LLM_JSON_MODE=json_schema`, если сервер это поддерживает (vLLM, LM Studio,
  свежий llama.cpp) — это заметно снижает число «битых» ответов;
* модели меньше 7–8B для этой задачи не рекомендуются: часто ломают JSON и путают дату события с датой публикации;
* «рассуждающие» модели (`*-reasoning`, `*-thinking`, R1) точнее, но в 3–10 раз медленнее и расходуют больше токенов —
  для еженедельного прогона по 80 сайтам достаточно быстрой модели с поиском.

## Регулярный запуск
* `deploy/run_audit.sh` — запуск с сохранением истории `reports/<дата>/` и `reports/latest/`;
* `deploy/crontab.example` или `deploy/gosweb-audit.{service,timer}` (systemd) — еженедельно;
* `deploy/Dockerfile` — контейнер (`docker run -v $PWD/reports:/app/reports image`).

Краулер устойчив к сбоям: повторы запросов с паузой, таймауты, недоступный сайт отмечается в отчёте
и не прерывает проверку остальных, упавшая отдельная проверка не роняет сайт. Все сайты региона обслуживаются
одним сервером, поэтому число одновременных запросов ограничено (`--concurrency`, по умолчанию 12).
Страницы кэшируются на 12 часов (`.cache/`), повторная сборка отчёта занимает секунды.

**Важно:** сайты `*.gosweb.gosuslugi.ru` могут быть недоступны из-за рубежа — запускать с российского сервера.

## Стоимость и ресурсы
* Базовый режим — без платных сервисов: Python 3.10+, ~80 МБ трафика, ≈ 6–10 тыс. HTTP-запросов на весь перечень.
* С `--llm` через шлюз: `gemini-2.5-flash` (≈ $0.27 / $2.25 за 1 млн токенов) + Google Search.
  Фактический замер: 2 новости на сайт, 80 сайтов → 120 запросов, 77 тыс. входных / 271 тыс. выходных токенов,
  **≈ $0.6 за прогон** (3 новости на сайт — ≈ $1). Ответы ИИ кэшируются в `.cache/llm/`, повторный прогон бесплатен.
  Через Anthropic API — `claude-opus-5-5` (меняется `--llm-model`). Локальная модель — бесплатно, но медленнее
  (на CPU — минуты на новость; уменьшайте `--llm-news`). Расход токенов выводится в отчёте.
* Время полного прогона: ≈ 12 минут на 80 сайтов (≈ 4–6 тыс. HTTP-запросов, ограничение 12 одновременных).

## Ограничения (честно)
* Если в новости нет даты события, срок публикации не проверяется — такие новости учитываются отдельно
  (метрика «с датой события» и замечание «не указана дата события»).
* Даты без года достраиваются по дню недели (если указан) или по ближайшей дате.
* Документ считается найденным по названию/тексту ссылки; содержимое PDF не анализируется.
* Качество фотографий (фон, освещение, деловой стиль, «перевёрнутый флаг») автоматически не оценивается —
  выявляются только отсутствующие фото и картинки-заглушки.
* Офлайн-факт-чекинг проверяет только формализуемые факты (даты, юбилеи, дни недели); остальное — через `--llm`.
* Разделы ищутся по меню, карте сайта и стандартным адресам шаблона; нестандартно названный раздел может быть
  не найден — такое замечание стоит перепроверить вручную.

## Структура кода
```
audit/
  cli.py         запуск, параллельная обработка сайтов
  fetcher.py     HTTP: повторы, лимит нагрузки, кэш, перцептивный хэш картинок
  discovery.py   поиск разделов по меню и /map/
  extract.py     парсеры: новости, мероприятия, документы, персоны, заглушки (не зависят от CSS-классов)
  dates.py       русские даты, кварталы, учебный год
  checks.py      проверки одного сайта
  factcheck.py   дата события, офлайн-факт-чекинг
  llm.py         ИИ-бэкенды: OpenAI-совместимый (облако/локально) и Anthropic; настройки AUDIT_LLM_*
  crossval.py    эталон, сравнение сайтов, заглушки-фото, балл
  report.py      HTML / XLSX / CSV
  templates/     шаблоны отчёта
data/institutions.csv   перечень учреждений из задания
tests/                  юнит-тесты (pytest)
```

## Локальная проверка через Ollama

Отдельный профиль `profiles/ollama.env` использует только `127.0.0.1:11434`, модель
`qwen3.5:9b-q4_K_M`, строгий JSON и отключённый веб-поиск. Облачный `.env` не изменяется.
Кэш локальной модели хранится отдельно в `.cache/local-ollama`.

Для базового аудита и облачной Gemini скачивание весов не требуется. На этой машине Ollama уже хранит локальную Qwen в `/var/lib/ollama/models`. Команда `ollama list` показывает установленный тег. Проверенная сборка `qwen3.5:9b-q4_K_M` занимает 6,55 ГБ, начало её идентификатора — `56671c2ab938`. На новом компьютере веса загружаются один раз командой ниже.

Первичная установка на нашем стенде Ubuntu x86_64 с NVIDIA. Скрипт проверяет драйвер через `nvidia-smi`. Для KVADRA D20 используй установщик из раздела о мини-ПК ниже.

```bash
bash scripts/install-ollama.sh
ollama pull qwen3.5:9b-q4_K_M
```

Скрипт использует официальный архив Ollama, не устанавливает драйверы, создаёт systemd-службу
и каталог весов `/var/lib/ollama/models` вне репозитория. Контекст сервера — 8192,
один запрос одновременно, одна загруженная модель. API слушает только loopback.

```bash
systemctl status ollama --no-pager
ollama list
ollama ps
nvidia-smi
sudo systemctl start ollama
sudo systemctl stop ollama
sudo systemctl restart ollama
journalctl -u ollama -n 50 --no-pager
ollama run qwen3.5:9b-q4_K_M
ollama stop qwen3.5:9b-q4_K_M
```

Одна проверка подключения через существующий краулер, без полного обхода:

```bash
scripts/audit-local llm-test
```

Для возврата к существующему облачному профилю запускайте обычную команду
`.venv/bin/python -m audit ...` из нового терминала без переменных `AUDIT_LLM_*`
в окружении. Локальный wrapper меняет окружение только своего процесса.
Облачные команды при настройке Ollama не запускаются.

Интеграционный тест `scripts/test-local-ollama.py` выполняет пять небольших проверок:
текст, JSON, изображение, `llm-test`, одна сохранённая новость. Все HTTP-запросы этого
тестового процесса ограничены `127.0.0.1:11434`; для каждого запуска создаётся свежий кэш
и сохраняются ответы, время и показания GPU в `.cache/ollama-smoke-*/`.
Для изображения и новости нужны предварительно подготовленные файлы
`/tmp/ollama-smoke-inputs/person.jpg` и `/tmp/ollama-smoke-inputs/news.json`.
Тест не запускает обход сайтов. Передача фотографий в обычном ИИ-модуле краулера
пока не реализована: визуальная проверка выполняется отдельно.

Проверено 7 ноября 2026: Ollama 0.40.15, `qwen3.5:9b-q4_K_M`, ID `56671c2ab938`,
8192 токена, один запрос. `ollama ps` показывает 100% GPU, журнал — 33/33 слоя на GPU.
Наблюдавшийся пик процесса — 6812 МиБ VRAM; общий пик GPU — 8370 МиБ, включая рабочий стол.
В журнале также есть CPU_Mapped-буфер 545,62 МиБ; это не CPU-offload вычислительных слоёв.

Для локального профиля задано `AUDIT_LLM_REASONING_EFFORT=none` и максимум 2048 токенов ответа:
с рассуждениями по умолчанию модель исчерпывала прежний лимит 4000 без итогового JSON.
В режиме без веб-поиска применяется отдельная инструкция, выдуманные URL не выдаются за источники.
Облачный профиль с веб-поиском сохраняет прежнюю инструкцию; его ключ не изменён.

Результаты небольших тестов: холодный текст 38,64 с (загрузка 21,39 с), JSON 0,41 с,
изображение 6,78 с, `llm-test` после настройки 2,73 с, сохранённая новость 3,08 с.
Это проверка подключения, не гарантия точности: модель ошиблась с цветом брюк на портрете
и вернула 2025 год вместо 2026 для события 29 сентября в новости от 1 октября 2026.
Существующий алгоритм извлёк для этой новости правильную дату. Внешний фактчекинг отключён.
Итоговый JSON — `.cache/ollama-verification.json`, исходные результаты сохранены отдельно.
Поэтому интеграционный тест возвращает ненулевой код на проверке точности даты; соединение работает.
Для повторения только двух тестов краулера: `.venv/bin/python scripts/test-local-ollama.py --crawler-only`.


Сравнение локальных моделей на фиксированных 30 примерах и защита расхождений дат:
см. [benchmarks/README.md](benchmarks/README.md). Текущий локальный профиль сохранён
на Qwen3.5 9B: в этом сравнении она дала меньше неверных дат, чем Qwen3 14B.
При расхождении дат алгоритма и ИИ краулер сохраняет кандидатов и помечает новость
для проверки, не назначая автоматически просрочку. Это отображается в HTML и JSON.

### Передача модели на KVADRA D20

KVADRA D20 выпускается с Intel Core i3, i5 или i7 десятого и одиннадцатого поколений и оперативной памятью DDR4. У демонстрационного экземпляра, по сведениям владельца, 32 ГБ ОЗУ. При контексте 4096 этого объёма должно хватить для CPU-запуска Qwen3.5 9B Q4_K_M вместе с краулером. Скорость стоит замерить на самом D20. Установщик Ollama выбирай под фактическую ОС; для Linux на этой платформе нужна сборка x86_64/amd64. [Спецификация производителя (PDF)](https://business.kvadra.tech/wp-content/uploads/%D0%94%D0%B0%D1%82%D0%B0%D1%88%D0%B8%D1%82-D20-2.10.pdf) · [Ollama для Linux](https://docs.ollama.com/linux) · [Ollama для Windows](https://docs.ollama.com/windows)

**Если на мини-ПК уже работает Ollama**, выполни эти команды заранее, пока есть интернет. Первая скачает сборку целиком, включая модуль для изображений. Вторая покажет её ID. Для проверенной версии он начинается с `56671c2ab938`. [Официальная сборка Qwen3.5 9B Q4_K_M](https://ollama.com/library/qwen3.5:9b-q4_K_M)

```sh
ollama pull qwen3.5:9b-q4_K_M
ollama list
ollama run --verbose --think=false qwen3.5:9b-q4_K_M "Новость опубликована 1 октября 2026 года. Встреча с инспектором состоялась 29 сентября. Ответь только датой встречи в формате ГГГГ-ММ-ДД."
ollama ps
```

Ожидаемая дата — `2026-09-29`. Повтори запрос дважды: первый замер включает загрузку холодной модели, второй показывает задержку после прогрева. `--verbose` выводит время и скорость генерации, а `ollama ps` показывает, где размещена модель. Для репетиции задай серверу `OLLAMA_CONTEXT_LENGTH=4096` и `OLLAMA_NUM_PARALLEL=1`, затем перезапусти его. [Настройки Ollama для каждой ОС](https://docs.ollama.com/faq) · [Поддерживаемые ускорители](https://docs.ollama.com/gpu)

На тестовом компьютере с Intel Core i9-13900KS мы отключили GPU для одного запроса через API. При контексте 4096 модель вернула верную дату, а Ollama показала 0 байт VRAM. Это проверяет возможность работы на CPU. Время ответа на экземпляре D20 предстоит измерить во время репетиции.

Проверь также запрос через сам краулер из ветки `AI-only-solution`. На Linux после установки зависимостей из «Быстрого старта» выполни `scripts/audit-local llm-test`. На Windows используй PowerShell из корня проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Get-Content .\profiles\ollama.env | ForEach-Object {
    if ($_ -match '^(AUDIT_\w+)=(.*)$') { Set-Item -Path "Env:$($Matches[1])" -Value $Matches[2] }
}
.\.venv\Scripts\python.exe -m audit llm-test
```

Профиль направляет запросы на локальный порт 11434. После установки зависимостей и скачивания весов можно отключить интернет для проверки автономного запуска. Живой обход сайтов требует сети. Готовый отчёт для показа открывается локально из `reports/latest/index.html`.

**Если программа принимает GGUF** и поддерживает архитектуру Qwen3.5, можно заранее скачать файлы напрямую на компьютер или флешку. При сохранении задай им расширение `.gguf`. Для обработки текста нужен первый файл, для изображений в совместимой программе — оба. Полная сборка Ollama вместе с настройками занимает 6,55 ГБ. [Скачать текстовые веса Q4_K_M, 5,63 ГБ](https://registry.ollama.ai/v2/library/qwen3.5/blobs/sha256:02d45dc1cf451ba2475ac33b301c2dd8f985abe4c182ce04a1f2f5bf0260278d) · [Скачать модуль изображений BF16, 0,92 ГБ](https://registry.ollama.ai/v2/library/qwen3.5/blobs/sha256:f836f08f921193f4d6b6a6952dba0a6fb116759d26a757bcb395d570d73976ca)

**Чтобы перенести нашу готовую сборку Ollama на флешке**, из корня проекта на исходной Ubuntu выполни команду ниже. Она читает семь файлов выбранной версии из локального хранилища. Пароль `sudo` вводится в этом терминале. Для архива нужен носитель, который принимает файл больше 4 ГБ, например exFAT.

```sh
sudo -u ollama tar -C /var/lib/ollama/models -cf - -T "$PWD/profiles/qwen3.5-9b-ollama-files.txt" > "$HOME/qwen3.5-9b-ollama.tar"
```

После успешного завершения скопируй `qwen3.5-9b-ollama.tar` на мини-ПК. Распакуй в отдельную папку: в её корне появятся `blobs` и `manifests`. Укажи полный путь к этой папке в переменной `OLLAMA_MODELS` **у процесса сервера Ollama**, дай ему доступ на чтение и запись и перезапусти Ollama. Проверь ID через `ollama list` и выполни тестовый запрос выше. [Как задать каталог моделей в своей ОС](https://docs.ollama.com/faq#where-are-models-stored)
