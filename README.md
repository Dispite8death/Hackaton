# ИИ-краулер для аудита сайтов школ и детских садов (Госвеб, Магаданская область)

Краулер автоматически обходит официальные сайты 40 школ и 40 детских садов на платформе «Госвеб»,
проверяет актуальность и полноту контента, определяет **эталонный сайт** для каждого типа учреждений,
сравнивает с ним остальные сайты и формирует понятный отчёт: где проблема, насколько она критична
и что исправить в первую очередь.

Решение подготовлено ИИ-агентом (ветка `AI-only-solution`).

## Быстрый старт

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m audit run                       # все 80 сайтов -> reports/latest/index.html
.venv/bin/python -m audit run --only sh-ola,ds5     # выборочно (подстроки доменов)
.venv/bin/python -m audit run --kind kindergarten   # только детские сады
.venv/bin/python -m audit run --llm                 # + факт-чекинг новостей ИИ-агентом (см. ниже)
```

Настройки ИИ — в файле `.env` (см. `.env.example`) или флагами; подробно — раздел [«Настройка ИИ»](#настройка-ии).
Проверить подключение одной командой: `.venv/bin/python -m audit llm-test`.

## Что проверяется

| Раздел | Школы | Детские сады | Проверка |
|---|:-:|:-:|---|
| Новости | ✓ | ✓ | интервал между публикациями ≤ 14 дней (за год, летние каникулы отмечаются мягче); давность последней новости; публикация ≤ 24 ч после события (дата события из текста: «23 октября», «21–25 сентября», «вчера»); **факт-чекинг** |
| Мероприятия | ✓ | (если есть) | наличие на текущий и следующий квартал; прошедшие мероприятия сверяются с новостями (новость в течение 2 недель) |
| Документы / Сведения об ОО | ✓ | ✓ | полный перечень документов со всех подразделов; 20 обязательных категорий (Приказ Рособрнадзора № 1493); актуальность отчёта о самообследовании; пустые подразделы; **сравнение с эталоном и другими сайтами** |
| Педагогический состав / Наш коллектив | ✓ | ✓ | фото (включая выявление силуэтов-заглушек шаблона), уровень образования, контакты (для детсадов) — по карточкам каждого сотрудника |
| О школе, Структура и органы управления | ✓ | | история учреждения, заполненность, фото руководителей, пустые страницы органов управления |
| Контакты / главная страница | ✓ | ✓ | телефон, e-mail, адрес, режим работы, часы приёма; для детсадов — контакты и режим работы на главной |
| Расписание | ✓ | | факт заполнения (модуль шаблона, файлы, картинки), актуальный учебный год |
| Реализуемые образовательные программы | ✓ | ✓ | наименования, форма, срок, язык, численность, тексты программ |
| Педагогам и сотрудникам | ✓ | ✓ | заполненность подразделов |
| Весь сайт | ✓ | ✓ | демо-контент шаблона из памятки «Типичные ошибки»: «Укажите ФИО», «Заголовок мероприятия №1», «Опишите…», «Примерно от … до … символов», «Задача 1», «статус», «Сайт в стадии разработки»; баннер ПОС |

### Факт-чекинг новостей
1. **Офлайн (бесплатно, всегда):** даты государственных праздников и памятных дат (32-ФЗ, указы Президента РФ,
   День Магаданской области), «N-летия» исторических событий и персоналий, соответствие дня недели дате,
   событие «в прошедшем времени» с датой позже публикации, сверка с разделом «Мероприятия».
2. **ИИ-агент (опция `--llm`, см. «Настройка ИИ»):** модель с веб-поиском (Gemini + Google Search через
   OpenAI-совместимый шлюз или Claude + web search; локальные модели — без поиска) определяет дату события и проверяет до 4 фактов новости по открытым источникам
   (официальные сайты, СМИ), возвращает JSON: подтверждено / расхождение / не подтверждено + источник.
   «Подтверждено» без найденных источников не засчитывается.

### Эталонный сайт и сравнение
Эталон — сайт с наибольшим баллом среди учреждений своего типа. Для остальных сайтов отмечаются
документы, которые есть у эталона **и** у большинства учреждений, а также разделы эталона, которых нет на сайте.
Картинки сотрудников сравниваются между сайтами по перцептивному хэшу: одинаковое изображение на нескольких
сайтах (или у нескольких сотрудников) — это заглушка шаблона.

### Критичность и балл
`Критично` (сайт недоступен, нет новостей > 45 дней, нет устава/лицензии, нет раздела педсостава) ·
`Высокая` (нарушение норм, видимые гражданам заглушки) · `Средняя` · `Низкая` (рекомендации).
Балл = 100·e^(−штраф/80), штраф 15/8/3/1, не более 25 на раздел. Шкала: ≥85 «Хорошо», ≥65 «Удовлетворительно»,
≥40 «Требует внимания», иначе «Критично».

## Настройка ИИ

ИИ используется только в режиме `--llm` (факт-чекинг новостей и уточнение даты события). Без него краулер
работает полностью и бесплатно на офлайн-проверках. Поддерживаются два типа бэкенда:

* **`openai`** — любой сервер с OpenAI-совместимым API `/v1/chat/completions`: облачные шлюзы
  (OpenRouter, LiteLLM, vLLM, корпоративный прокси) **и локальные модели** (Ollama, LM Studio, llama.cpp server, vLLM);
* **`anthropic`** — Anthropic API (Claude с серверным веб-поиском).

### Параметры

Задаются переменными окружения или в файле `.env` в корне проекта (читается автоматически, в git не попадает;
шаблон — `.env.example`). Флаги командной строки имеют приоритет над `.env`.

| Переменная | Флаг CLI | По умолчанию | Что регулирует |
|---|---|---|---|
| `AUDIT_LLM_PROVIDER` | `--llm-provider` | `auto` | `openai` / `anthropic`. `auto`: если задан `AUDIT_LLM_BASE_URL` — `openai`, иначе `anthropic` |
| `AUDIT_LLM_BASE_URL` | `--llm-base-url` | — | адрес OpenAI-совместимого сервера **до** `/chat/completions`, например `https://openrouter.ai/api/v1`, `http://localhost:11434/v1` |
| `AUDIT_LLM_API_KEY` | — (только env/.env) | — | ключ, отправляется как `Authorization: Bearer …`. Для локальных серверов не нужен — оставьте пустым |
| `AUDIT_LLM_MODEL` | `--llm-model` | `gemini-2.5-flash` (openai) / `claude-opus-5-5` (anthropic) | идентификатор модели так, как его понимает сервер (`/v1/models`) |
| `AUDIT_LLM_WEB_SEARCH` | `--llm-web-search` | `auto` | `google` — передать инструмент `googleSearch` (Gemini за прокси Vertex/LiteLLM); `off` — без веб-поиска; `auto` — `google` для моделей с «gemini» в названии, иначе `off` |
| `AUDIT_LLM_JSON_MODE` | — | `json_object` | как просить JSON: `json_object`, `json_schema` (строгая схема — vLLM, LM Studio, OpenAI) или `off`. Если сервер режим не поддерживает (HTTP 400/422), краулер сам повторит запрос без него |
| `AUDIT_LLM_TIMEOUT` | — | `120` | таймаут запроса, секунд (для локальных моделей на CPU ставьте 300–600) |
| `AUDIT_LLM_MAX_TOKENS` | — | `4000` | лимит длины ответа |
| `ANTHROPIC_API_KEY` | — | — | ключ для `anthropic` (или профиль `ant auth login`) |
| `AUDIT_CACHE_DIR` | `--cache-dir`* | `.cache` | кэш страниц и ответов ИИ (`.cache/llm/`) — повторный прогон не тратит токены |

\* `--cache-dir` задаёт кэш страниц; кэш ответов ИИ берётся из `AUDIT_CACHE_DIR`.

Сколько новостей на сайт отправлять в ИИ — флаг `--llm-news` (по умолчанию 3).

### Примеры

```bash
# Облачный OpenAI-совместимый шлюз с Gemini + Google Search
AUDIT_LLM_BASE_URL=https://<шлюз>/v1  AUDIT_LLM_API_KEY=<ключ>  AUDIT_LLM_MODEL=gemini-2.5-flash

# OpenRouter / любой OpenAI-совместимый провайдер без встроенного поиска
AUDIT_LLM_BASE_URL=https://openrouter.ai/api/v1  AUDIT_LLM_API_KEY=<ключ>  AUDIT_LLM_MODEL=qwen/qwen3-235b-a22b

# Локально: Ollama (ollama serve; ollama pull qwen2.5:14b)
AUDIT_LLM_BASE_URL=http://localhost:11434/v1  AUDIT_LLM_MODEL=qwen2.5:14b  AUDIT_LLM_TIMEOUT=600

# Локально: LM Studio (вкладка Developer → Start server)
AUDIT_LLM_BASE_URL=http://localhost:1234/v1  AUDIT_LLM_MODEL=<id модели из LM Studio>  AUDIT_LLM_JSON_MODE=json_schema

# Локально: vLLM / llama.cpp server
AUDIT_LLM_BASE_URL=http://localhost:8000/v1  AUDIT_LLM_MODEL=<имя модели>

# Anthropic API
AUDIT_LLM_PROVIDER=anthropic  ANTHROPIC_API_KEY=<ключ>
```

Разовый запуск без правки `.env`:

```bash
.venv/bin/python -m audit run --llm --llm-base-url http://localhost:11434/v1 --llm-model qwen2.5:14b
```

Проверка настроек (один тестовый запрос с новостью, в которой заведомо неверная дата Дня отца):

```bash
.venv/bin/python -m audit llm-test
.venv/bin/python -m audit llm-test --llm-base-url http://localhost:11434/v1 --llm-model qwen2.5:14b
```

### Как учитывается веб-поиск

* **С веб-поиском** (`google` или Claude) статусы «подтверждено» / «расхождение» засчитываются, только если
  в ответе есть ссылки на найденные источники — они показываются в отчёте.
* **Без веб-поиска** (большинство локальных и OpenAI-совместимых моделей) модель всё равно определяет дату
  события, но её вердикты по фактам помечаются как «не подтверждено (мнение модели: …)» и **не влияют на оценку**:
  модель без поиска может ошибаться. Пример из проверки: `gemini-2.5-flash-lite` без поиска уверенно назвала
  неверную дату Дня отца. Офлайн-проверки (памятные даты, юбилеи, дни недели) работают при любом бэкенде.
* Если у модели нет поиска, а проверка по источникам нужна, используйте модель с поиском (Gemini за прокси
  с `AUDIT_LLM_WEB_SEARCH=google`) или `anthropic`.

## Регулярный запуск
* `deploy/run_audit.sh` — запуск с сохранением истории `reports/<дата>/` и `reports/latest/`;
* `deploy/crontab.example` или `deploy/gosweb-audit.{service,timer}` (systemd) — еженедельно;
* `deploy/Dockerfile` — контейнер (`docker run -v $PWD/reports:/app/reports image`).

Краулер устойчив к сбоям: повторы запросов с паузой, таймауты, недоступный сайт отмечается в отчёте
и не прерывает проверку остальных, упавшая отдельная проверка не роняет сайт. Все сайты региона обслуживаются
одним сервером, поэтому число одновременных запросов ограничено (`--concurrency`, по умолчанию 12).
Страницы кэшируются на 12 часов (`.cache/`), повторная сборка отчёта занимает секунды.

**Важно:** сайты `*.gosweb.gosuslugi.ru` могут быть недоступны из-за рубежа — запускать с российского сервера.

## Стоимость и ресурсы
* Базовый режим — без платных сервисов: Python 3.10+, ~80 МБ трафика, ≈ 6–10 тыс. HTTP-запросов на весь перечень.
* С `--llm` через шлюз: `gemini-2.5-flash` (≈ $0.27 / $2.25 за 1 млн токенов) + Google Search.
  Фактический замер: 2 новости на сайт, 80 сайтов → 120 запросов, 77 тыс. входных / 271 тыс. выходных токенов,
  **≈ $0.6 за прогон** (3 новости на сайт — ≈ $1). Ответы ИИ кэшируются в `.cache/llm/`, повторный прогон бесплатен.
  Через Anthropic API — `claude-opus-5-5` (меняется `--llm-model`). Локальная модель — бесплатно, но медленнее
  (на CPU — минуты на новость; уменьшайте `--llm-news`). Расход токенов выводится в отчёте.
* Время полного прогона: ≈ 12 минут на 80 сайтов (≈ 4–6 тыс. HTTP-запросов, ограничение 12 одновременных).

## Ограничения (честно)
* Если в новости нет даты события, срок публикации не проверяется — такие новости учитываются отдельно
  (метрика «с датой события» и замечание «не указана дата события»).
* Даты без года достраиваются по дню недели (если указан) или по ближайшей дате.
* Документ считается найденным по названию/тексту ссылки; содержимое PDF не анализируется.
* Качество фотографий (фон, освещение, деловой стиль, «перевёрнутый флаг») автоматически не оценивается —
  выявляются только отсутствующие фото и картинки-заглушки.
* Офлайн-факт-чекинг проверяет только формализуемые факты (даты, юбилеи, дни недели); остальное — через `--llm`.
* Разделы ищутся по меню, карте сайта и стандартным адресам шаблона; нестандартно названный раздел может быть
  не найден — такое замечание стоит перепроверить вручную.

## Структура кода
```
audit/
  cli.py         запуск, параллельная обработка сайтов
  fetcher.py     HTTP: повторы, лимит нагрузки, кэш, перцептивный хэш картинок
  discovery.py   поиск разделов по меню и /map/
  extract.py     парсеры: новости, мероприятия, документы, персоны, заглушки (не зависят от CSS-классов)
  dates.py       русские даты, кварталы, учебный год
  checks.py      проверки одного сайта
  factcheck.py   дата события, офлайн-факт-чекинг
  llm.py         ИИ-бэкенды: OpenAI-совместимый (облако/локально) и Anthropic; настройки AUDIT_LLM_*
  crossval.py    эталон, сравнение сайтов, заглушки-фото, балл
  report.py      HTML / XLSX / CSV
  templates/     шаблоны отчёта
data/institutions.csv   перечень учреждений из задания
tests/                  юнит-тесты (pytest)
```
