### Запуск из корня проекта

```powershell
.\.venv\Scripts\python.exe .\Engine\loadPage.py --list
.\.venv\Scripts\python.exe .\Engine\loadPage.py --org 1
.\.venv\Scripts\python.exe .\Engine\loadPage.py --org 1 41 --max-pages 22 --max-depth 3
.\.venv\Scripts\python.exe .\Engine\loadPage.py --all
.\.venv\Scripts\python.exe .\Engine\loadPage.py --org 1 41 --coverage
.\.venv\Scripts\python.exe .\Engine\loadPage.py --all --coverage
```

Каждый запуск загрузки добавляет новые снимки. Команда `--coverage` использует последний обход каждого выбранного учреждения и читает результат из базы. По каждому обязательному пункту выводится одно из четырёх наблюдений — сохранена страница раздела, найден заголовок, найдена ссылка, пока не найдено. Заголовок «История школы» внутри «О школе» позволяет перейти к проверке истории даже у учреждения без отдельной страницы для неё.

Для работы с историей `page.date_loaded` содержит время получения в секундах Unix. Таблица `crawl_run` хранит учреждение, время и пределы обхода, `crawl_fetch` связывает запрошенный адрес и HTTP-результат со снимком. В `crawl_link` можно восстановить путь от исходной страницы к найденному материалу, в `crawl_heading` — прочитать подпись тематического заголовка на конкретной странице.

Например, этот запрос показывает, с каких страниц первого детсада в списке ведут ссылки на документы. Он берёт последний обход учреждения с ID 41.

```sql
SELECT DISTINCT f.final_url AS source_page, l.label, l.url AS document_url
FROM crawl_link AS l
JOIN crawl_fetch AS f ON f.id = l.fetch_id
WHERE f.run_id = (SELECT MAX(id) FROM crawl_run WHERE id_organization = 41 AND purpose = 'audit')
  AND l.relation = 'document'
ORDER BY source_page, document_url;
```

### Получение HTML для проверки директора

Капитан взял на себя алгоритм проверки карточки директора. Codex подготовил функцию `get_homepage_html(conn, organization_id)` в [saved_pages.py](Engine/saved_pages.py) и выгрузил [главную Инженерной школы](samples/home-1.html) из базы как пример. Категория главной страницы — `home`, глубина — 0. Функция возвращает строку с HTML последнего успешного снимка или `None`. Для экспорта другого примера в новый файл из корня проекта:

```powershell
.\.venv\Scripts\python.exe .\Engine\saved_pages.py --org 5 --section home --out home-5.html
```

Для выбора по полному названию в той же команде предусмотрен `--name`. В Python `get_organization_id(conn, name)` находит ID, а `get_homepage_html(conn, organization_id)` читает снимок. При совпадении названий нескольких учреждений утилита выводит их ID для выбора.

### Карточки сотрудников и браузерная проверка

**Решения капитана.** Начать с главной и знакомого шаблона Госвеба, при изменении вёрстки искать общий блок должности, имени и фото, при необходимости перейти во внутренние разделы. Хранить сотрудников в таблице существующей SQLite. Собирать HTML и браузерные свидетельства в момент обхода, чтобы позже использовать их для разных отчётов и визуальной проверки моделью. Проверять видимость с учётом CSS и перекрытия баннером. Капитан обратил внимание на сайты, у которых печать обрезает длинную страницу до высоты окна.

**Реализация Codex.** Подключены Beautiful Soup и опциональный Playwright. Дописаны функции капитана в [Alghorithm_section.py](Engine/Alghorithm_section.py). Добавлены [разбор карточек](Engine/staff_extract.py), [поиск по сохранённым разделам](Engine/scan_staff.py), [браузерный захват](Engine/browser_capture.py) и [проверка видимости отдельных полей](Engine/staff_render.py). Codex провёл обходы и проверил результаты по SQLite, снимкам и файлам PDF.

В требованиях к разделам «О школе», «Наш коллектив» и «Педагогический состав» указаны фотография, уровень образования и контактные данные. В школе отдельно проверяется блок «Структура и органы управления». Поиск руководителя на главной — выбранный командой порядок обхода. Если главная не дала кандидата, проверяются скачанные разделы руководства и коллектива, дополнительные страницы и связанные профили. Наличие адреса фото подтверждает только ссылку в карточке. [Критерии оценки](Задание/Критерии_оценки_ИИ-краулер.docx)

В `search.sqlite3` хранится история наблюдений.

- `staff_observation` связывает одну карточку с конкретным снимком `page.id`. Поля включают ФИО, должность, признак руководителя, ссылку на фотографию и профиль, образование, телефон и почту. У фотографии различаются ссылка, известная заглушка и отсутствие. У одного человека может быть несколько наблюдений.
- `staff_element` хранит проверяемое поле карточки, CSS-селектор, ожидаемое значение и результат его проверки. Архивный HTML без браузерного замера получает `pending`. Браузер различает видимость в исходном окне, выход за экран, скрытие стилями, частичную видимость и перекрытие. При недостаточных данных сохраняется `unknown`.
- `page_render` связывает с тем же посещением время, фактический URL, размер окна, состояние CSS, отрисованный DOM, JPEG первого окна и длинный JPEG. По флагу `--pdf` добавляется PDF с экранными стилями. Метаданные отмечают ограничения размера снимка, внутреннюю прокрутку и отличия печатной вёрстки. Медленная сборка DOM может дать частичный снимок, тогда поиск сотрудников работает по исходному HTTP-ответу.

По последним основным обходам 80 учреждений проверены 543 тематических HTML-снимка из 1756. В 469 из них найдено 3121 наблюдение карточек и выделено 13 515 элементов для проверки. У 73 учреждений алгоритм нашёл одного кандидата в руководители на главной, у 5 — только во внутренних разделах (ID 25, 32, 52, 58, 79). У 2 учреждений остались разные кандидаты. В школе с ID 28 главная и раздел управления называют директоров с разными фамилиями. У детсада с ID 67 должность «Заведующий» указана у четырёх разных сотрудников одной страницы педагогического состава (снимок 1154).

Команда `home_audit.py scan` повторно разбирает сохранённые снимки с текущим словарём. [Извлечение фото и описания](Engine/home_content.py) · [Извлечение мероприятий](Engine/home_events.py)

### Как проверяются даты мероприятий и кварталы

**Правило предложил капитан.** Сначала читать выделенный календарь самой карточки. Если там нет года, сверить день и месяц с датами текста этой же карточки. Если в тексте две разные даты или дата расходится с календарём, сохранить пометку «Возможная ошибка дат» и материалы для сверки.

**Реализация и проверка Codex.** [Разбор дат](Engine/home_events.py) сохраняет текст календаря, селекторы и цитаты из описания. Два повторения одного и того же дня считаются одним свидетельством. Если единственная полная дата точно согласуется с календарём, год восстанавливается с указанием `calendar_confirmed_by_card_text`. У спорной записи сохраняется причина `possible_date_error`. Метки по снимкам доступны в представлении `school_event_date_issue` и в консольном отчёте. [Сводка по кварталам](Engine/event_quarters.py) учитывает часовой пояс Магадана на дату обхода, интервалы с переходом года и повторные ссылки на одну карточку. Пропуски пагинации, незавершённый обход и неразобранные даты сохраняются в основаниях результата.

- На примере **Ягодного**, в календаре диктанта указано «14 октября, среда». Две цитаты из текста указывают на один день — **14 октября 2026 года**. Запись из главной (1145), списка (1166) и подробной страницы (1258) учтена один раз в IV квартале 2026 года. [Пакет для просмотра и передачи модели](samples/yagodnoe-home-1145/review.json)
- У **эколого-биологического лицея**, ID 7, олимпиада с 1 сентября 2026 года по 31 мая 2027 года пересекает IV квартал 2026 года и I квартал 2027 года. В каждом периоде она учтена по одному разу.
- У **Инженерной школы**, ID 1, в календаре тематической недели стоит 26 февраля, а в тексте упоминается 1 марта (снимок 27). Это пример расхождения для сверки: в описании может быть дата памятного дня. Во всех основных обходах 9 разных URL получили год из текста, по 13 разным URL сформированы пометки о возможной ошибке дат. Для IV квартала датированные кандидаты найдены у двух школ, для I квартала — у одной. Эти числа относятся к сохранённым страницам и не доказывают отсутствие событий у остальных школ.

### Допустимые источники фактчекинга

**Решение капитана.** Администратор сам добавляет и удаляет базовые URL издателей, на которые система может опираться при подтверждении события. Настройка доступна в окне.

**Реализация Codex.** Во вкладке «Источники» можно разрешить весь сайт или конкретный раздел. База `https://example.org/news/` подходит для `/news/report`. Адрес `/newsletter/report`, другой поддомен и другая схема требуют самостоятельного разрешения. Параметры запроса и фрагменты в поле базового адреса отклоняются. Для статьи проверяются введённый или найденный URL, каждый переход и конечная страница. Ограничения на ресурсы учреждений и перепечатки действуют вместе со списком. Каждая проверка сохраняет применённые базовые URL и контрольную сумму списка. Ранее записанные результаты доступны в истории. Пустой список сохраняется после перезапуска и отключает внешний поиск. [Редактор](Engine/admin.py) · [Правила URL](Engine/factcheck_sources.py)

Codex подготовил шесть стартовых базовых URL, все можно удалить. Поиск в индексе использует до двух запросов с ограничением по сайтам или разделам, по шесть базовых URL на запрос. При более длинном списке выбор адресов для этих запросов зависит от ID снимка. Найденные через любую поисковую площадку статьи проверяются по всему списку. [Поиск и сохранение доказательств](Engine/factcheck.py)

На снимке 1258 в проверке № 7 две вручную указанные статьи прошли проверку по допустимым базовым URL и подтвердили проведение диктанта. Для участия школы подтверждений осталось ноль. Третий контрольный URL вне списка был отклонён до чтения. Повторная индексация очереди не потребовала обращения в сеть. Полный регрессионный прогон с окном администратора и Chromium прошёл **222 из 222 тестов**.

Для внешнего показа подготовлена отдельная копия баз и файлов, локальная модель, восстановление исходных настроек и ручное включение на время просмотра. Проверены внешний вход, запрос к модели, сброс параметров и просмотр распакованного архива.
